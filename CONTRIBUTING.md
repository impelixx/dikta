# Contributing

## Локальная разработка

```bash
npm install
npm run tauri dev
```

Модель нужно скачать один раз прямо в приложении: Настройки → «Модель распознавания» → «Скачать».

## Структура проекта

```
src/                 фронтенд главного окна (TS, без фреймворка)
src/overlay.ts        фронтенд плавающего оверлея
src-tauri/src/
  lib.rs               точка входа, трей, окна, роутинг команд
  hotkeys.rs           логика push-to-talk/toggle, живые субтитры, VAD-watcher
  audio.rs             cpal-обвязка, ресемплинг, снапшоты буфера
  asr.rs               FFI-обёртка sherpa-rs-sys (CTC и Transducer)
  models.rs            каталог моделей, скачивание, кастомные HF-модели
  db.rs                SQLite: история, статистика, настройки
  paste.rs             автовставка + безусловный fallback в буфер
  vad.rs               детектор тишины по RMS
  settings.rs          структура и (де)сериализация настроек
  commands.rs          Tauri-команды, вызываемые из фронтенда
src-tauri/examples/
  decode_test.rs        ручная проверка ASR-пайплайна на тестовом WAV
  benchmark_models.rs   замер реальной скорости всех моделей каталога
site/                 промо-страница (статика, без сборки)
```

## Перед PR

```bash
cd src-tauri
cargo build
cargo test --lib
cd ..
npm run build
```

Если правили что-то в `hotkeys.rs`, `audio.rs` или `asr.rs` — по возможности
проверьте вручную через `npm run tauri dev`: хоткей → живая волна в оверлее →
распознанный текст. Это не покрыто автотестами (нужен реальный микрофон и
разрешения ОС), поэтому здесь особенно легко сломать что-то незаметно.

## Стиль коммитов

Коротко и по делу, на русском или английском — как удобнее. Одна логическая
перемена на коммит.

## Модели и лицензия

При добавлении в каталог новой встроенной модели (`models.rs::builtin_catalog`)
обязательно измерьте реальную скорость через `cargo run --example
benchmark_models --release`, а не оценивайте на глаз — в интерфейсе цифры
подаются как факт, а не маркетинг.
